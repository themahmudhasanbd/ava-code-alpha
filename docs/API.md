# AvA Code Alpha v2 API Documentation

Comprehensive REST, Server-Sent Events (SSE), WebSocket, and JSON-RPC 2.0 API reference for the AvA Code Alpha autonomous software engineering platform.

---

## 1. Overview & Architecture

The AvA Code Alpha App-Server daemon is a modular, high-performance runtime built on Bun. It acts as the central orchestration bridge between the Flutter Mobile / Web client, local VPS toolchains, MCP servers, and LLM model gateways (OmniRoute, Antigravity, and OpenAI-compatible providers).

### Base URLs
- **Local VPS**: `http://127.0.0.1:4096`
- **Public Domain**: `https://ava.mahmudhasan.pro`
- **OmniRoute Proxy**: `http://127.0.0.1:20128/v1`

### Modular Architecture
```
apps/server/src/
├── index.ts                # Master entrypoint, server routing, and WebSocket upgrades
├── config/                 # Environment defaults, CORS, token auth, and safe path resolution
├── types/                  # TypeScript domain interfaces
├── services/
│   ├── storage.ts          # Persistent JSON stores (sessions, custom providers, memories, scheduler, FCM)
│   ├── sse.ts              # SSE client connections manager and global/session broadcaster
│   ├── agent.ts            # Autonomous agent streaming engine (OmniRoute, Antigravity, OpenAI-compatible)
│   ├── mcp.ts              # MCP client manager (stdio spawn & remote HTTP tools)
│   ├── terminal.ts         # PTY & subprocess command execution
│   ├── git.ts              # Git repository status, diffs, and branch resolution
│   ├── scheduler.ts        # Cron & background task runners
│   └── fcm.ts              # FCM notification token manager and push dispatcher
└── routes/
    ├── auth.ts             # Authentication, profile management, and avatars
    ├── sessions.ts         # Sessions CRUD, prompt dispatch, messages, and interactive replies
    ├── events.ts           # SSE global and session event streaming
    ├── models.ts           # Dynamic providers and models, test connection, Antigravity OAuth
    ├── workspace.ts        # File tree, file edit, upload, download, media, and git status
    ├── mcp.ts              # MCP server CRUD and tool execution
    ├── memory.ts           # Persistent memories search, stats, and CRUD
    ├── system.ts           # Health, system stats, PM2 process management, and permissions
    ├── skills.ts           # Custom agent skills CRUD
    ├── tasks.ts            # Background tasks and cron scheduler
    ├── notifications.ts    # FCM token registration and push testing
    ├── webhooks.ts         # Webhook subscriptions and test dispatches
    ├── terminal.ts         # Terminal command execution
    └── rpc.ts              # JSON-RPC 2.0 protocol endpoint
```

## 3. API Reference

### 3.1 System & Health

#### `GET /health` / `GET /api/health`
Returns current server status, active engine, version, and default workspace.
- **Response**:
```json
{
  "status": "healthy",
  "engine": "AvA Code Alpha v2",
  "version": "v0.1.0-alpha",
  "provider": "omniroute",
  "workspace": "/",
  "uptimeSeconds": 443
}
```

#### `GET /api/system/stats`
Returns system memory, CPU load, and OS architecture metrics.
- **Response**:
```json
{
  "platform": "linux",
  "arch": "x64",
  "memory": {
    "totalMb": 15987,
    "freeMb": 8420,
    "usedMb": 7567,
    "usagePercent": 47
  },
  "cpu": {
    "cores": 8,
    "model": "AMD EPYC",
    "loadAvg": [0.15, 0.22, 0.31]
  }
}
```

#### `POST /api/system/process/restart`
Restarts a PM2 managed process.
- **Body**: `{"name": "ava-server"}`
- **Response**: `{"success": true, "output": "..."}`

#### `GET /api/system/logs?lines=50&name=ava-server`
Fetches recent log output for the specified process.

### 3.2 Authentication & User Profile

#### `POST /api/auth/login`
Authenticates user and returns a signed JWT token.
- **Body**: `{"username": "mahmudhasan", "password": "..."}`
- **Response**:
```json
{
  "success": true,
  "token": "ey...",
  "user": {
    "username": "mahmudhasan",
    "name": "Mahmud Hasan",
    "role": "admin",
    "avatar": "https://ava.mahmudhasan.pro/icons/Icon-192.png"
  }
}
```

#### `GET /api/user/profile`
Returns current profile information.

#### `POST /api/user/profile`
Updates profile metadata (name, email, etc.).

#### `POST /api/user/profile/avatar`
Updates profile avatar URL or data URI.

### 3.3 Sessions & Chat Execution

#### `GET /session` / `GET /api/session`
Lists recent sessions. Supports query parameters `?limit=50&directory=/`.

#### `POST /session`
Creates a new conversation session.
- **Body**:
```json
{
  "title": "Build Feature X",
  "model": { "id": "powerful-coding-combo", "providerID": "omniroute" },
  "workingDirectory": "/"
}
```

#### `GET /api/session/active`
Returns the current active session object.

#### `GET /session/:id`
Returns session detail, turn count, and message list.

#### `GET /session/:id/message`
Returns formatted array of messages with Opencode / AvA v2 schema:
```json
[
  {
    "info": {
      "id": "msg_0",
      "role": "user",
      "time": { "created": 1789994877 }
    },
    "parts": [{ "id": "part_0", "type": "text", "text": "Calculate 25 * 4" }]
  },
  {
    "info": {
      "id": "msg_1",
      "role": "assistant",
      "time": { "created": 1789994882 },
      "model": { "id": "powerful-coding-combo", "providerID": "omniroute" }
    },
    "parts": [{ "id": "part_1", "type": "text", "text": "25 * 4 = 100." }]
  }
]
```

#### `POST /session/:id/prompt_async`
Dispatches a user prompt to the autonomous agent and returns immediately with queue status while broadcasting progress over SSE:
- **Body**:
```json
{
  "prompt": "Inspect Nginx reverse proxy logs",
  "model": { "id": "powerful-coding-combo", "providerID": "omniroute" }
}
```
- **Response**: `{"success": true, "sessionId": "session_123", "status": "queued"}`

#### `POST /session/:id/interrupt`
Immediately stops the ongoing agent turn for the session.

#### `POST /session/:id/fork`
Forks the session and its history into a new branch.

#### `POST /session/:id/mode`
Switches agent persona mode (`build`, `plan`, `research`, `shell`).

#### `POST /session/:id/model`
Updates default model and provider for the session.

### 3.4 Real-time Streaming & Server-Sent Events (SSE)

#### `GET /api/event` / `GET /event`
Opens a persistent global SSE event stream.
- **Event Types Emitted**:
  - `connected`: Initial connection acknowledgment.
  - `status`: Execution status (`running`, `idle`).
  - `message.part`: Real-time text and reasoning chunks:
    ```json
    { "type": "message.part", "part": { "type": "text", "text": "Hello" }, "sessionId": "...", "textDelta": "Hello" }
    ```
  - `session.next.text.delta`: Forward-compatible incremental delta.
  - `tool_use` / `tool_finish`: Tool execution lifecycle events.
  - `ask_question`: Interactive agent question awaiting user selection.
  - `permission_request`: Command confirmation prompt.
  - `error`: Dynamic error message extracted from upstream/local tools.
  - `done`: Turn completion with final reply and token usage.

#### `GET /session/:id/stream`
Session-scoped SSE stream.

### 3.5 Providers & Models

#### `GET /api/models`
Discovers and lists all models across all enabled providers.

#### `GET /api/providers`
Returns provider list and configured custom providers.

#### `POST /api/provider/test`
Validates connection and retrieves models from an OpenAI-compatible endpoint.
- **Body**: `{"baseUrl": "http://127.0.0.1:20128/v1", "apiKey": "sk-..."}`

#### `POST /api/provider/add`
Registers a new custom provider.

#### `POST /api/provider/toggle`
Enables or disables a custom provider.

#### `POST /api/provider/delete`
Deletes a custom provider.

#### `GET /api/provider/antigravity/status`
Returns connection status and active accounts for Google Antigravity.

### 3.6 Workspace & Files

#### `GET /api/workspace/files?path=/var/www`
Lists directory contents with directory and file metadata.

#### `GET /api/workspace/file?path=/path/to/file.txt`
Reads text content of a file.

#### `POST /api/workspace/file`
Writes or overwrites a text file.
- **Body**: `{"path": "/path/to/file.txt", "content": "..."}`

#### `DELETE /api/workspace/file?path=/path/to/file.txt`
Deletes a file or directory.

#### `POST /api/workspace/upload`
Uploads binary or text file via `multipart/form-data`.

#### `GET /api/workspace/git/status?path=/var/www/ava-code`
Returns git branch, modified count, and short status.

### 3.7 Model Context Protocol (MCP)

#### `GET /api/mcp`
Lists registered MCP servers and status (`connected`).

#### `POST /api/mcp/add`
Adds a new MCP server.
- **Body**: `{"name": "mysql-mcp", "type": "local", "command": "node", "args": ["/path/to/server.js"]}`

#### `POST /api/mcp/test`
Tests MCP stdio process or remote URL and lists exposed tools.

#### `POST /api/mcp/toggle`
Enables or disables an MCP server.

---

### 3.8 Persistent Memories

#### `GET /api/memory/list`
Lists persistent memories with optional `?category=architecture` filter.

#### `POST /api/memory/add`
Stores a new persistent memory item.
- **Body**: `{"title": "Database Schema", "content": "Postgres on port 5432", "category": "architecture"}`

#### `GET /api/memory/search?q=database`
Full-text search across persistent memories.

#### `GET /api/memory/stats`
Returns total count and memory distribution by category.

---

### 3.9 Terminal & Tasks

#### `POST /api/terminal/exec`
Executes bash command on VPS.
- **Body**: `{"command": "pm2 list", "cwd": "/"}`
- **Response**: `{"stdout": "...", "stderr": "", "exitCode": 0}`

#### `GET /api/scheduler/tasks`
Lists scheduled cron tasks.

#### `POST /api/scheduler/tasks`
Creates a scheduled task.
- **Body**: `{"name": "Nightly Backup", "cron": "0 2 * * *", "command": "bash /root/backup.sh"}`

#### `POST /api/scheduler/tasks/:id/run`
Manually triggers immediate execution of a scheduled task.

### 3.10 JSON-RPC 2.0 (`/rpc`, `/v2/rpc`)

Standard JSON-RPC 2.0 endpoint supporting:
- `auth/login`: Authenticates user.
- `session/list`: Lists threads.
- `session/create`: Creates session.
- `session/get`: Retrieves session.
- `model/list`: Lists models.
- `provider/list`: Lists providers.
- `mcp/list`: Lists MCP servers.
- `memory/list`: Lists memories.

Example Request:
```json
{
  "jsonrpc": "2.0",
  "method": "session/list",
  "id": 1
}
```
